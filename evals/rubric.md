# 生成质量评分维度

## 启用状态

v1 **不启用自动评分**。评测对象是「gold 锚点是否进入 top-k」，可由人工标注直接判定，纯计算即可完成；LLM-as-judge 的调用量是「组数 × 样本数 × 生成 × 打分」的乘法增长，与总调用上限 50 次冲突（`constitution.md` 规格裁剪表）。本文件只保留人工观察维度，结果不进任何指标、不进 CI。

## 人工观察维度（v0.5 `/ask` 演示时使用）

| 维度 | 观察内容 | 记录方式 |
| --- | --- | --- |
| 事实一致 | 答案陈述与检索到的条文是否一致 | 一致 / 部分偏差 / 矛盾 |
| 引用有效 | 答案引用的条款 id 是否全部落在本次 top-k 内 | 全部有效 / 含越界引用 |
| 完整性 | 是否覆盖问题所需的关键条款 | 完整 / 缺关键条款 |
| 拒答合理性 | 检索为空或相关度低时是否明确说明而非编造 | 合理 / 编造 |

## 记录位置

演示观察结果写入 `PROGRESS.md` 的演示记录段，不写入 `evals/` 指标文件，不参与版本推进判定。
