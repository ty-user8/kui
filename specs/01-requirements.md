# 需求说明

## 1. 问题与目标

企业内部文档检索的常见失败不是「模型不够强」，而是「召回结果无法验证、改动无法判断好坏」。本项目用一批可公开分发的法规 DOCX 建立一条**可复现的检索评测链路**：同一 `run_id` 下，任何对外给出的数字都能用一条命令重新算出来。

目标不是做一个聊天机器人，而是回答三个问题：检索召回得怎么样、改动之后变好还是变坏、坏在哪一环。

## 2. 目标用户与核心场景

| 项 | 内容 |
| --- | --- |
| 主要用户 | 招聘方与技术面试官（现场演示与追问）；次要用户为需要按条款查法规的同事 |
| 使用方式 | 单轮查询，输入一句中文问题，返回命中的法规条文及其 doc_id、标题路径与字符区间 |
| 优先级 1 | 按问题找条款：用口语或术语描述一个法律问题，找出对应的那一条 |
| 优先级 2 | 按编号或术语精确匹配：`专利法第五十三条`、`专利代理师资格证` 这类含编号与专名的查询 |
| 优先级 3 | 现场复现指标：一条命令跑完评测，两次输出一致 |
| 容错容忍度 | 允许「检索不到就返回空并说明」，**禁止编造**条文；不追求覆盖率，追求可解释 |

## 3. 量化成功指标

只认可复现，不设 Recall 绝对门槛（D-005）。

| 指标 | 判定方式 | 适用版本 |
| --- | --- | --- |
| 输出一致性 | 同一 `run_id` 连跑两次，评测输出逐字节一致（耗时字段另存） | v0.1 起 |
| 锚点可映射率 | 30 条 gold 锚点 100% 能映射到 chunk；`unmapped` 计数为 0 | v0.1 |
| 评测回路调用量 | LLM 调用 0 次（无 API key 环境下可完整跑完） | v0.1 起 |
| 指标可解释 | 每个对外数字附一条复现命令 | v0.1 起 |
| 检索质量变化 | 相对重跑基线的 Recall@5 / MRR 差值 + bootstrap 区间，区间重叠不计为提升 | v0.2 起 |

## 4. 能力范围一句话

输入一批只读 DOCX，切分成带稳定锚点的 chunk，用「向量 + BM25 融合 → rerank」检索，用人工标注的 gold 锚点纯计算出指标，并把每一环的中间结果写进 trace。

范围边界见 `02-scope.md`。

## 5. 评测口径

### 5.1 gold 锚点格式

每条案例记录：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `case_id` | 案例编号 | `C001` 起，不复用 |
| `version_introduced` | 该案例引入的版本 | `v0.1` / `v0.2` |
| `split` | 用途划分 | `dev` / `holdout` |
| `query` | 查询文本 | 中文，模拟真实提问，禁止直接抄条文原句 |
| `doc_id` | 目标文档标识 | 取自 `manifest.json`，不是文件名 |
| `article_no` | 目标条款编号 | 如 `第二十二条`；无条号文档留空 |
| `heading_path` | 章节路径 | 如 `第五章专利权的期限、终止和无效` |
| `anchor_text` | `[char_start, char_end)` 回切的整段文本，供人工核对 | 逐字取自基准文本，必须与区间回切结果完全一致 |
| `char_start` / `char_end` | 锚点字符区间 | 左闭右开，基准见 5.3；由工具从 DOCX 基准文本抽取回填，人工只做确认 |
| `difficulty` | 难度标签 | 编号敏感 / 术语 / 同义改写 / 数值 / 列举 / 否定 / 跨文档区分 |
| `anchor_status` | 标注状态 | `candidate`（Agent 起草）/ `confirmed`（人工确认） |

**锚点的生成分工**：`candidate` 状态只适用于 `query` 字段——query 由 Agent 起草，人工确认措辞。`anchor_text` 与 `char_start` / `char_end` **一律由回填工具从 DOCX 基准文本抽取**，不使用任何生成式手段起草或用 LLM 确认（技术方案 B1）：工具输入 `doc_id` + `article_no`，定位该条整段，切片得到 `anchor_text` 与区间，回切校验通过后落盘。人工只做确认或驳回，`anchor_status` 只有人工可以改为 `confirmed`。

`evals/cases.csv` 现行的 `anchor_text` 为初次抽取值，基准文本冻结后由回填工具统一覆盖；`char_start` / `char_end` 目前为空，由同一工具填入。语料含 3 组同名不同公布日期的法规（水法、商标法、农业法各 2 版，共 6 篇）。gold 锚点一律以 `doc_id` 区分，不得只写标题；系统不按标题合并文档（REQ-057），因此同名旧版仍可被检索到，评测时也不会互相顶替。

### 5.2 指标定义

单条 query 只有一个 gold 锚点（v0.1~v0.2）。

| 指标 | 定义 |
| --- | --- |
| Hit@k | gold 锚点映射到的 chunk 出现在前 k 位则为 1，否则 0 |
| Recall@k | `Σ Hit@k / 案例数` |
| MRR | `mean(1 / rank_first_hit)`；未命中记 0 |
| nDCG@5 | 二值增益，`DCG = Σ gain_i / log2(i+1)`，IDCG 取理想单条命中位置 1 |
| HitRate@5 | 与 Recall@5 数值相同（单 gold 情形），保留双列以便 v2 多 gold 扩展 |
| unmapped | gold 锚点无法映射到任何 chunk 的案例数，单独计数，不计入 Hit 分母之外 |

### 5.3 字符区间基准层

锚点是「原文位置」，必须只依赖文档本身，不依赖切分。基准定义如下，实测数据来自 `corpus/docs` 全量 150 篇（26558 段）。

#### 5.3.1 基准文本的构造

按 `document.paragraphs` 的顺序（即 body 下 `w:p` 的文档顺序）逐段取 `paragraph.text`（段内按 run 顺序拼接，不插空格），**段落之间插入单个 `\n`**；空段落保留为空段，因此会出现连续 `\n`。分隔符不属于任何段落的字符区间。

各构造元素的处理方式：

| 元素 | `python-docx` 表现 | 基准文本处理 | 计入 SHA-256 | 语料实测 |
| --- | --- | --- | --- | --- |
| 正文文本 `w:t` | 拼入 `run.text` | 原样保留 | 是 | 40536 处 / 150 篇 |
| 制表符 `w:tab` | `run.text` 中为 `\t` | 保留为 `\t`，计 1 字符 | 是 | **0 处** |
| 软换行 `w:br` / `w:cr` | `run.text` 中为 `\n` | 保留为 `\n`，计 1 字符 | 是 | 13 处 / 8 篇，其中 3 篇 4 段位于标题折行 |
| 域代码 `w:fldSimple` / `w:instrText` / `w:fldChar` | 不进入 `paragraph.text` | 域**结果**文本按 run 计入；域**指令**不计入 | 结果计入，指令不计入 | **0 处** |
| 脚注／尾注 `w:footnoteReference` | 不进入 `paragraph.text` | 引用标记不占正文位置；脚注正文不读 | 否 | **0 处** |
| 超链接 `w:hyperlink` | `paragraph.text` 只取 `w:r` 直接子节点 | 不计入；若后续语料出现须重导基准文本 | 否 | **0 处** |
| 图片 `w:drawing` / `w:pict` | 无文本 | 不计入，仅记 `non_text_count` | 否 | 9 处 / 4 篇 + 3 处 / 1 篇 |
| 表格 `w:tbl` | `document.paragraphs` 不含表格内段落 | 不计入，见 5.3.1.1 | 否 | 1 篇 |
| 页眉／页脚／批注／文档属性 | 不在 body 段落内 | 不读 | 否 | — |

**段内 `\n` 与段间分隔符同为 `\n`，歧义的处理**：段落边界不由基准文本反推，而由 ingest 时的段落序列决定（内存中记录每段 `[start, end)` 偏移）。任何需要段落边界的地方都从该序列取，禁止解析文本猜边界。

**为什么不做 strip 与空白折叠**：语料实测全角空格 14126 处、半角空格 0 处，段首缩进与条号后的间隔都用 `\u3000` 表示。一旦 strip 或折叠，偏移将不再等于原文位置，锚点无法与 DOCX 原件逐字对照。

#### 5.3.1.1 表格不计入基准

全量语料仅 1 篇含表格（《电力安全事故应急处置和调查处理条例》，5 行 6 列，单元格文本 2205 字，约占该文档 25%）。该表单元格内为竖排单字（如「特\n别\n重\n大\n事\n故」），按行列拼接会产生无语义片段，反而污染检索。

v1 的处置：表格文本不计入基准文本；`documents` 表记 `tables_count`，质量报告标记 `HAS_TABLE_UNINDEXED`，该文档在检索评测中只用其段落正文。若要把表格纳入基准，须另出变更单——会改变该文档的基准文本与 SHA-256，需重导其锚点。

#### 5.3.2 索引侧文本与基准文本的偏移映射

**原则**：索引侧文本必须是基准文本的**等长副本**，不允许增删字符（禁止 strip、禁止空白折叠、禁止删除重复字符）。据此 `base_offset ≡ index_offset`，映射恒等。

- **v0.1~v0.2（normalizer_version = 0）**：索引侧不做任何字符变换，`chunk.char_start` / `char_end` 直接是基准偏移。断言 `normalize_index(base) == base`（逐字节相等）。该断言**只在 `normalizer_version = 0` 时成立**；一旦启用新版本，断言按版本分支——`nv = 0` 走逐字节相等，`nv ≥ 1` 走 `len(idx2base) == len(index_text)` + 单调不减 + 末值 < `len(base_text)` 三条。
- **查询侧归一化**（全半角、空白折叠、简繁）只作用于 query，不产生任何偏移，也不写回基准。
- **若未来必须引入增删字符的索引侧变换**（例如清除水印残留），必须同时提供逐字符映射数组 `idx2base`（长度等于归一化文本长度，每个元素为该字符在基准文本中的偏移），chunk 仍只存基准偏移，并在 `documents` 记 `normalizer_version` 与 `index_text_sha256`。
- **保序约束**：`idx2base` 单调不减的前提是变换**保序**——只允许增、删、改字符，**禁止任何重排**（交换、逆序、块移动）。断言：对归一化文本任意 `i < j`，恒有 `idx2base[i] <= idx2base[j]`。需要重排的变换视为不支持，必须换实现或另出变更单。
- **`normalizer_version` 进 `run_id`**：该值写入 `run_id`（B8 可复现字段），不只记在 `documents` 表；两次运行若 `normalizer_version` 不同，即视为不同 `run_id`。
- 映射规则变更属契约变更，走变更单；变更后必须重导全部 `char_start` / `char_end`。

#### 5.3.3 偏移单位与区间含义

1. **偏移单位**：Unicode 码点（Python `str` 下标），起点 0，区间左闭右开。
2. **区间含义**：锚点区间覆盖「第X条」这一整段（从段首到段尾，不含段后分隔符）。

#### 5.3.4 校验与 SHA-256

1. 基准文本的 SHA-256 写入 `documents.text_sha256`，作为「同 doc_id 内容是否变化」的判据；索引侧若做变换，另算 `index_text_sha256`，不覆盖前者。
2. 锚点回切：按 `[char_start, char_end)` 从基准文本切片，与 `anchor_text` 逐字比对，不一致即判标注失效。
3. **SHA-256 的计算范围**：只含 5.3.1 表中标记「计入」的元素，不含表格、图片、页眉页脚、域指令与脚注正文。

#### 5.3.5 映射与命中判定

- **v0.1~v0.2（固定长度切分）**：gold 起点落在 chunk 区间内即视为该 chunk 命中。理由：固定长度切分必然切断长条款，若要求 chunk 完整覆盖锚点，长条款会恒为 miss，指标反映的是切分长度而非检索质量。
- **v0.3 起（父子 chunk）**：统一映射到 parent 段落级锚点，要求 parent 区间完整覆盖 gold 区间。

#### 5.3.6 实施前提

本节已随 G1 冻结。锚点回填工具按此实现；若基准改为依赖 `python-docx` 之外的工具（如直接解 XML），视为基准变更，须重导基准文本并重填全部 `char_start` / `char_end`。

## 7. 术语

| 术语 | 含义 |
| --- | --- |
| 基准文本 | 按 5.3 从 DOCX 生成的唯一文本，字符偏移的参照 |
| 稳定锚点 | `doc_id` + 标题路径 + 字符区间，不随切分策略变化 |
| 锚点映射 | 把 gold 锚点按区间关系对到当前切分下的 chunk |
| `run_id` | 一次可复现实验的标识，含种子、模型版本、切分参数、评测集哈希 |
| holdout | 封存的评测子集，调参阶段不读取，最后只跑一次 |
| unmapped | 锚点无法映射到任何 chunk 的案例计数 |
