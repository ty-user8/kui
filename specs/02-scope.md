| 项 | 取值 | 说明 |

### 2.1 两篇文档的选型理由

| 文档 | 结构特征 | 覆盖的验收条款 |
| --- | --- | --- |
| 专利法 | 全部段落为 `Normal` 样式；含「目　　录」段，章名在目录与正文各出现一次（共 16 行） | REQ-003（跳过目录）、REQ-004（样式缺失时的正则兜底） |
| 专利代理条例 | 使用 `Heading 1` 样式，无目录 | REQ-004（样式路径） |

两篇同为专利主题、一为法律一为行政法规，天然构成「上位法与下位法」的干扰对：查询写「专利代理师执业要实习多久」时，专利法全文无对应条文，只有代理条例第十一条命中，可直接检验跨文档区分能力。

**v0.1 语料规模的已知限制**：2 篇基准文本合计 14925 字（条文本 8116 字）、114 条、**实测 34 个 chunk**（26 + 8），Recall@5 随机基线 **5/34 ≈ 14.7%**，指标区分度有限。v0.1 的职责是跑通闭环与验证可复现，**不得用它的指标判断检索质量**。

**v0.2 全量语料实测（T-010，2026-11-18）**：150 篇全部入库，基准文本合计 1,191,197 字、**2704 个 chunk**（每篇中位 16、均值 18、最大 79），表格排除 2205 字（仅 1 篇含表格），召回池由 34 扩至 2704，Recall@5 随机基线降至 5/2704 ≈ 0.18%；同名多版本 3 组 6 篇按 `doc_id` 各占一行、未合并。索引体积实测 5,675,789 字节（约 5.42 MB）。

### 2.2 v0.1 完成定义（DoD）

`evals/cases.csv` 现有的 30 条只是**候选集**。v0.1 的完成定义如下，三项标注条件为硬门禁：

| # | 条件 | 判定方式 |
| --- | --- | --- |
| 1 | 30 条 `anchor_status` 全部由人工改为 `confirmed`，未确认数为 0 | 读 CSV 计数 |
| 2 | `char_start` / `char_end` 由工具从 DOCX 基准文本（5.3）回填，`anchor_text` 按区间回切校验逐字一致 | 回填工具日志 + 30 条全通过 |
| 3 | 锚点可映射率 100%，`unmapped` = 0 | `eval.py` 输出 |
| 4 | 同一 `run_id` 连跑两次：分别落 `attempt-1/` 与 `attempt-2/`，两份 `metrics.json` 逐字节一致，`run_id` 不变 | diff 两个 attempt 目录 |
| 5 | 评测回路 LLM 调用 0 次（无 `RAG_LLM_API_KEY` 环境可完整跑完） | 环境变量清空后跑通 |
| 6 | 指标齐全：Recall@1/3/5、MRR、nDCG@5、HitRate@5 | `eval.py` 输出 |

**门禁语义**：第 1~3 项未全部达成前，不得进入 Implement 的检索与评测任务，也不得宣称 v0.1 通过。（锚点回填工具是 v0.1 的第一个任务，它的产出正是第 1~2 项的前置——人工确认在工具产出之后进行。）

`candidate` 状态只适用于 `query`；`anchor_text` 与区间一律由工具从 DOCX 基准文本抽取，人工只做确认，Agent 不得起草 gold，也不得以任何生成式手段补全锚点。

## 3. 能力清单（做什么）

1. 解析只读 DOCX，产出带 `doc_id`、`article_no`、`heading_path`、字符区间的基准文本与 chunk。
2. 三种切分策略可切换，父子 chunk 只索引小片、返回大段。
3. 向量单路检索，v0.2 起加 BM25 与 RRF 融合，v0.3 起加本地 rerank。
4. 人工锚点评测集 + 纯计算指标，同一 `run_id` 可复现。
5. 全链路 trace：两路召回、融合、重排、命中、耗时。
6. 三条降级路径：向量异常退 BM25、rerank 超时退融合排序、过滤 0 结果放宽。
7. 确定性状态机编排的四个接口（`/search`、`/eval`、`/ingest`、`/trace`）。
8. 演示页与最小生成层（`/ask`），生成层不进指标。

## 4. 评测集与 holdout 规则

- v0.1：30 条，`split` 列按「每 5 条取第 5 条」划分，得 24 dev + 6 holdout；holdout 在 v0.1 不参与任何调参（v0.1 无调参），仅封存。
- v0.2：补至 100 条，其中 20 条为 holdout（v0.1 的 6 条 + 新增 14 条）；调参阶段只读 `split=dev` 的 80 条，holdout 最后跑一次并如实报告回落。
- **换集必须重跑基线**：v0.2 在新集上重跑 v0.1 配置作为新基线，不沿用 v0.1 的 30 条数字；基线替换须经变更单确认。
- **锚点由人工确认**：新增 70 条由 Agent 起草为 `candidate`，`anchor_status` 只有人工可改为 `confirmed`；未确认的锚点不计入指标，其数量在输出中单列。
- **同名多版本**：3 组同名不同公布日期的法规（水法、商标法、农业法各 2 版）按 `doc_id` 视为独立文档，不按标题合并，锚点以 `doc_id` 区分（REQ-057）。

## 5. 明确不做

| 不做 | 理由 |
| --- | --- |
| 生成质量评测 | `答案正确率 = f(检索质量, 模型能力)`，两个自变量无法反推；评测边界划在检索层 |
| 多跳 / 依赖型推理 | 需多轮检索与生成，归为已知限制并在边界外话术中说明 |
| LLM 自主规划（ReAct / 自我反思） | 每轮调用 LLM，按轮数放大，与 50 次上限冲突 |
| 知识图谱 / GraphRAG | 索引阶段需对全库反复调用 LLM |
| 微调 / 训练 embedding | 瓶颈在召回不在生成 |
| LLM 造 gold 标注、LLM-as-Judge 全量回归、HyDE、逐 query 查询改写 | 调用量乘法增长，且破坏可复现性 |
| LLM-as-judge 评分 | 评测对象是可离线计算的检索命中，配额无法覆盖乘法增长（`evals/rubric.md` 仅保留人工评分维度） |
| 分布式、云端向量库、鉴权、多租户 | 与「单机 CPU 可运行」冲突 |
| 跨会话记忆、多轮问答 | 属 v2；v1 无状态是设计选择（D-002） |
| MD 输入、第三方语料 | 官方不提供 MD；第三方语料授权与元数据口径不同（CHG-001） |
| PDF 进检索索引 | 仅作解析层对照，进索引须另出变更单（CHG-001） |
| 任何删除数据的能力 | 本项目不提供清库命令（REQ-055） |
| embedding 横向对比（text2vec-base-chinese、m3e-base、bge-base） | v1 固定 `BAAI/bge-small-zh-v1.5`，三个候选写入 `04-tech-choice.md` 的「候选 + 放弃理由」，不进任何版本与指标；更换按选型变更单处理 |
| 按标题合并同名多版本文档 | 版本判断需额外规则，且会让 3 篇旧版无法被检索；v1 以 `doc_id` 区分（REQ-057） |

## 6. 边界外请求的应对

| 请求类型 | 应对 | 返回内容 |
| --- | --- | --- |
| 「我这个情况算不算侵权」这类要结论的法律意见 | 不给结论 | 返回相关条文原文、`doc_id`、条款号与出处；附「仅检索条文，不构成法律意见」的说明 |
| 需要跨多部法衔接推理的问题 | 单跳检索，说明限制 | 返回单条最相关条文，并标注「多跳推理不在支持范围」 |
| 要求直接生成答案（v0.1~v0.4） | 无生成层 | 返回条文原文与锚点，不拼接、不改写 |
| 语料之外的法规或非法规文档（合同、论文） | 明确不支持 | 返回空结果并说明「当前语料仅含 150 篇法规 DOCX」 |
| 要求修改语料或补充文档 | 拒绝并说明流程 | 语料只读，新增文档须走变更单 |
| 要求清空索引或删除数据 | 拒绝 | 解释需人工手动操作文件，命令层不提供该能力 |

## 7. 规模与合规边界

- 文档数千篇以内、chunk 十万以内、单机 CPU、内存目标 < 4GB、并发个位数、无 SLA。
- 语料为公开法规 DOCX，来源与依据见 `corpus/README.md`（著作权法第五条）。README 标注来源与许可证。
- trace 只记锚点与 ≤80 字摘要，不落完整原文，不记密钥与用户目录。
- 仅使用可公开分发的文档；不引入含个人信息、内部资料或企业机密的内容。
