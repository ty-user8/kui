# Prompt 规格

## 启用状态

**v0.1~v0.4 豁免；v0.5 起启用**（T-027，2026-11-20）：

| 文件 | 用途 |
| --- | --- |
| `ask.system.v1.md` | 系统提示：只用给定条文、必须标 `[chunk_id]`、不足则说明、不补条款号、不提供法律意见 |
| `ask.user.template.v1.md` | 用户消息模板，占位符 `{query}`、`{context}`；缺占位符在加载时即报错 |

版本号由 `src/generate/ask.py` 的 `PROMPT_VERSION` 指定（`ask.system.v1`），随 `/ask` 响应返回，**不进 `run_id`**。

### 历史（v0.1~v0.4 豁免）

豁免理由：这四个版本无生成层，检索、切分、融合、重排、评测全为纯计算，不存在需要模型遵循的指令文本。硬填会造成空壳规格，违反「规格是机器可读契约」的前提。

## v0.5 启用时须补齐

| 文件 | 内容 | 约束 |
| --- | --- | --- |
| `ask.system.md` | 系统 Prompt：只依据给定条文回答、不得编造、引用格式 `[chunk_id]`、无相关内容时说明 | 独立文件，文件名含语义版本，如 `ask.system.v1.md` |
| `ask.user.template.md` | 用户消息模板：查询 + top-k 片段（含 `chunk_id` 与条款号） | 占位符固定为 `{query}`、`{context}` |
| `README.md` 增补 | 决策点：何时调用、何时拒答、引用校验规则 | 与 `07-api/` 的 `/ask` 契约一致 |

### `/ask` 的验证状态（如实记录）

`/ask` 的 200 路径**尚未用真实模型跑过**：开发机没有 `RAG_LLM_API_KEY`。已验证的是——引用校验、超时熔断、配额、缺 key 报错、无命中不调模型，以及「真实索引 + 假客户端」的响应拼装；这些都由单测与服务层覆盖。接上真 key 后需完整跑一次并补记录，才算这一条链路验证完毕。

边界不变：`/ask` 不进任何指标、不进 CI 回归，也不影响 `run_id` 与基线。

## 生成层的硬约束

1. 单次调用超时 30 秒，超时返回检索结果并标 `ASK_TIMEOUT`（REQ-049）。
2. 输出引用必须落在本次 top-k 内，规则式字符串匹配校验，0 次额外调用（REQ-050）。
3. 不进任何指标、不进 CI（REQ-051）；改动只记 `PROGRESS.md`（规则 #7）。
4. Prompt 版本号写入调用日志，便于复盘，但不进 `run_id`（不进评测回路）。
