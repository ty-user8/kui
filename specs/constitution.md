# 项目宪法（Agent 任何时候不得违反）

本文件是 RAG 检索与评测项目的最高约束。后续所有规格、代码与交付物与此冲突时，以本文件为准；需要变更本文件时走变更单并重新过门禁。

## 技术红线

1. **输入边界校验**：外部输入在入口校验——文件类型白名单（v1 仅 `.docx`）、单文件大小上限、路径穿越（拒绝 `..` 与绝对路径拼接）、OOXML 包结构（`PK\x03\x04` 开头）与 ZIP 解压规模上限。
2. **密钥不进任何文件**：`RAG_LLM_API_KEY` 只从环境变量读取，禁止写入代码、`config.yaml`、文档、日志与 git 历史。模型名与接口地址属**非密钥**，可写进 `config.yaml`（`llm.model_name`／`llm.base_url`）；同名环境变量 `RAG_LLM_MODEL`／`RAG_LLM_BASE_URL` 保留作覆盖（`CHG-012`）。缺 key 时明确报错，不静默降级。
3. **DB 写操作必须事务**：`documents` / `chunks` / `parents` 的批量写入在同一事务内，失败整批回滚，禁止留下半批数据。
4. **契约绑定 Schema**：所有工具接口、数据结构、LLM 输出均有显式 Schema（Pydantic 或 JSON Schema），校验失败按 `11-errors.md` 重试或报错，禁止静默兜底。
5. **评测回路 0 次 LLM 调用**：检索指标、参数网格、CI 回归、holdout、参数选型全部纯计算。违反此项的结果一律作废。
6. **输入材料只读**：`标准开发流程SOP.md`、`RAG检索项目技术方案_2026-11-14.md`（含 `specs/00-source/` 归档副本）、`corpus/docs/**`、`corpus/metadata/**`（尤其 `file_name`）、`corpus/tools/collect.py`（含其按 `tools/` 上两级推导根目录的逻辑）一律不改。
7. **依赖不擅自新增**：新增第三方包先在 `04-tech-choice.md` 列出用途、体积与备选，获确认后安装。禁止用 `--force` / `--legacy-peer-deps` 类参数绕过版本冲突。
8. **生成物与第三方不改**：`data/`、`.cache/` 下产物不手工编辑，改源文件后重新生成。

## 安全红线

1. **高危动作人工确认**：删除、外发数据、资金操作、`push` 一律需明确确认。本项目 v1 不提供任何删除命令，不提供清库入口。
2. **外部内容视为不可信输入**：DOCX 正文、文件名、元数据字段进入日志或 SQL 前一律按数据处理，不做 `eval` / `exec` / 模板求值。
3. **日志脱敏**：trace 只存 `doc_id`、锚点区间、分数、耗时与**不超过 80 字的正文摘要**，不落完整原文；不记录密钥、绝对路径中的用户名。
4. **不 push 到 main、不 force push**；未获明确确认前只允许本地 commit。
5. **不擅自删改用户文件**：删除、批量重命名、整体重写前先列受影响清单并等确认。

## 代码规范

- **命名**：模块与文件 `snake_case`；函数 `动词_名词`（`load_docx`、`build_index`）；类 `PascalCase`；常量 `UPPER_SNAKE`；私有函数前缀 `_`。标识符用英文，禁止拼音缩写。
- **注释语言**：中文；docstring 说明参数含义、取值范围、返回结构与异常，不写空话。
- **类型注解**：对外函数与数据结构必须标注参数与返回类型。
- **格式化与 Lint**：环境未提供 ruff／black／pytest，自检用标准库 `python -m compileall` 加运行时冒烟；引入 ruff／pytest 须按依赖流程先确认。
- **禁用项**：硬编码绝对路径（`config.yaml` 与环境变量除外）、硬编码密钥、`except: pass`、无责任人的 `TODO`、`breakpoint()`／`pdb`、提交前残留的调试 `print`（CLI 正常输出除外）。
- **交付说明文本**：按 SOP 规则 #11 与附录 C 执行，判定一律以附录 C 为唯一清单。`src/**` 注释、`README.md`、脚本用法文本、日志字段说明、提交信息属适用对象；`specs/**`、`evals/**`、`PROGRESS.md`、`CHANGELOG*.md`、变更单属过程留痕材料，不受此约束。Verify 前按附录 C.4 方式 2 做关键词扫描，扫描范围严格限定在适用对象。
- **扫描关键词表**（可增补）：`本文`、`初稿`、`配套`、`生成`、`本次`、`低配额版`、`修订`、`草稿`、`被问到`、`JD`。命中后区分「禁用写法」与「必要技术说明」，禁用写法必须改写，不得一律删除。

## 项目特定规则

固定约定见上表。三条原则：

- **DON'T**：不改动未要求改动的文件或配置；不顺带重构。
- **ALWAYS**：改动前先读目标文件，禁止凭记忆盲改；先读规格，代码与规格冲突时停下报告，不私自改任一方。
- **ALWAYS**：完成后用实际命令验证（编译、运行、请求），不得只声明「已完成」；改代码同步更新注释与文档。

## 工作流形态与版本

- **形态**：确定性流水线（无 LLM）。步骤与顺序在代码中固定，无模型决策；v0.5 生成层也是固定三步（检索 → 拼 Prompt → 引用校验）。不评估 router／并行／编排者-工作者／评估-优化四类模式。
- **版本路线**：

| 版本 | 范围 | 生效依据 | LLM API |
| --- | --- | --- | --- |
| v0.1 | 2 篇文档、固定长度切分、向量检索、30 条锚点评测、`eval.py` 打印 Recall@5 / MRR，纯命令行 | 同一 `run_id` 连跑两次输出完全一致；锚点 100% 可映射 | 0 |
| v0.2 | BM25 + jieba + RRF、评测集 100 条 + 20% holdout、trace、2~3 组实验 | 融合相对重跑基线 Recall@5 提升，holdout 不翻转 | 0 |
| v0.3 | 三种切分 + 父子 chunk + 标题路径、本地 rerank、bootstrap 区间 | rerank 前后 MRR／nDCG@5 差值 + p95 延迟代价表，区间重叠不算提升 | 0 |
| v0.4 | FastAPI 四接口、元数据过滤 + 三条降级、增量入库、状态机编排、CI | Schema 校验通过、关掉向量库能退 BM25、CI 复现同一数字 | 0 |
| v0.5 | Streamlit、README／架构图、`/ask` 生成层、失败案例归因 | 冒烟脚本可重复执行且自动清理 | 约 20~30 |

- **推进门槛**：指标可复现 + 代码可运行无半成品 + 决策写入 `CHANGELOG-DECISIONS.md`，三条齐才进下一版。
- **v0.1 不建** FastAPI／Streamlit／Docker。

## 状态与记忆

- **v1 无状态**：`f(query, config)` 为纯函数，同一 query 恒返回同一结果；不存会话记忆，无失效策略。理由是可复现性，不是资源限制。
- **v2 规划**：触发条件为产品形态变为多轮问答；隔离约束为 `/search`、`/eval`、CI 永远无状态，`run_id` 增 `stateless_mode=true`，评测时记忆模块强制关闭。记忆不得进入检索评测回路。

## 明确不做

| 不做 | 理由 |
| --- | --- |
| 把生成质量当检索指标 | `答案正确率 = f(检索质量, 模型能力)`，两个自变量无法反推 |
| 多跳／依赖型推理 | 需多轮检索与生成，归为已知限制 |
| LLM 自主规划（ReAct／自我反思） | 每轮调用 LLM，按轮数放大 |
| 知识图谱／GraphRAG | 索引阶段调用量远超朴素 RAG |
| 微调／训练 embedding | 瓶颈在召回不在生成 |
| LLM 造 gold 标注、LLM-as-Judge 全量回归、HyDE、逐 query 查询改写 | 调用量乘法增长，且破坏可复现性 |
| 分布式、云端向量库、鉴权、多租户 | 与单机 CPU 可运行目标冲突 |
| 跨会话记忆与多轮问答 | 属 v2，v1 无状态 |
| MD 输入、第三方语料 | 官方不提供 MD；第三方语料授权与元数据口径不同（CHG-001） |
| PDF 进检索索引 | 仅作解析层对照，进索引须另出变更单（CHG-001） |

## 低配额硬数字

- 评测回路 LLM 调用：**0 次**（铁律）。
- 总调用上限：**50 次**；分配：演示 ≤20、批量归因 ≤5、评测集 query 候选 1、缓冲 ≥30%。
- 单次调用超时：**30 秒**；`/ask` 带熔断，超时即返回检索结果与提示，不重试追加上限。
- 本地 embedding／rerank 不占 API 配额，但消耗 CPU／内存／时间，p50／p95 必须实测入表。

## 门禁与验收

- **门禁人工执行**：无工具强制，靠用户逐阶段明确确认。
- **成功指标**：只认可复现——同一 `run_id` 连跑两次输出完全一致、锚点可映射 100%、每个数字有一键复现命令。不设 Recall 绝对门槛。
- **统计口径**：百条样本下 1 条 = 1 个百分点，2~3 点差异不谈显著；用 bootstrap 给区间；holdout 只跑一次并如实报告回落。
- **无 CI 版本**：v0.1~v0.3 用「同一 `run_id` 连跑两次输出完全一致」代替 CI 绿灯，禁止编造 CI 结果。
